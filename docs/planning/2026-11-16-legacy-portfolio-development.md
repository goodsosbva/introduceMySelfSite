## 2. 추천 페이지 순서

첫 화면 → 기존 대화형 소개 → Profile과 Experience → Projects → Skills → Certifications → Contact

상단 메뉴와 기존 섹션 순서를 유지하고 자격증 연결만 추가한다. 경력은 기존처럼 프로필 안에 배치한다. 기술에서 사용 사례를 누르면 관련 프로젝트로 이동한다.

첫 화면은 기존 사진과 중앙 정렬 구성을 유지한다. 인사말 줄바꿈 제안:

> 안녕하세요
> 권현성입니다.

기존의 FRONTEND DEVELOPER 라벨, 사진과 소셜 링크 인터랙션을 유지한다. ‘사용자에게는 편리한 화면을, 동료에게는 함께 쓰기 좋은 구조를.’ 문구는 기존처럼 Profile에 둔다.

## 3. Skills: 기술명과 사용 경험을 연결

분야별 세 행을 기본으로 사용한다. 모든 기술이 기본 화면에 보이도록 하여 첫 구현에는 탭을 넣지 않는다. 기술 칩에는 작은 아이콘과 이름을 함께 쓰고, 로고 색은 채도를 낮춰 기존 푸른색 인상과 맞춘다.

| 분야 | 기본 노출 기술 | 사용 경험을 설명할 문구 |
| --- | --- | --- |
| Frontend | Vue 3, React, TypeScript, Next.js, Ant Design Vue, Redux | Vue 3와 TypeScript를 사용한 업무 화면 및 공통 UI 개발. React와 Next.js는 실무와 개인 프로젝트의 사용 범위를 각각 표시한다. |
| UI와 협업 환경 | Storybook, pnpm, Nx | 공통 컴포넌트 개발, 사용 가이드 정리, 모노레포 설정 및 패키지 분리 참여. |
| 프로젝트 확장 경험 | OpenLayers, Module Federation, Playwright, Python, LangGraph, RAG | CityWatch의 지도와 모듈 연결, Common Tester의 근거 검색과 테스트 생성 흐름에 적용. |

React의 회사 실무 사용은 현재 메인의 기술 목록에 기록되어 있다. 구체적인 사용 범위가 상세에 명확하지 않은 기술은 설명을 확대하기 전에 경력 내용과 대조한다. 확장 기술 전체를 실무 숙련 기술로 표현하지 않는다.

기술별 수치형 숙련도, 별점, 진행률은 사용하지 않는다. 대신 ‘실무 사용’과 ‘프로젝트 적용’이라는 텍스트를 표시한다. 색만으로 경험 수준을 구분하지 않는다.

## 4. Projects: 대표 세 개의 판단 근거를 노출

데스크톱에서는 미리보기와 설명을 좌우로 배치한 프로젝트 행 세 개를 권장한다. 세로로 긴 카드보다 기존의 편집형 구성을 이어가기 좋다. 모바일에서는 미리보기 아래에 설명을 배치한다.

각 프로젝트의 고정 정보 순서:

1. 실무 / 개인 / 협업 구분
2. 프로젝트 이름과 한 줄 설명
3. 담당 역할과 기여 범위
4. 핵심 기술 네 개 안팎
5. 대표 구현 두 가지
6. 상세 보기와 공개 저장소 링크

| 순서 | 프로젝트 | 메인에서 보여줄 내용 | 미리보기 및 연결 |
| --- | --- | --- | --- |
| 01 | 공통 UI | 테이블과 버튼 개발 및 개선 참여. 모노레포 설정, 패키지 분리와 Storybook 사용 가이드 제공에 기여. | 기존 상세의 테이블 예시를 재구성한 미리보기. ‘구성 예시’라고 표시. `case-common-table.html` 연결. |
| 02 | CityWatch FE Lab | 도시 안전 관제를 주제로 기술을 적용한 개인 프로젝트. X-Ray로 화면과 코드 연결, 지도와 상태 공유, 모듈 연결을 설명. | `assets/citywatch-practice.png` 등 실제 화면 재사용. `case-citywatch.html`과 공개 GitHub 연결. |
| 03 | Common Tester | 협업에서 사용한 테스트 생성기. 요구사항 근거, 생성 코드, 실행 결과를 이어서 확인하는 흐름을 설명. | `assets/common-tester-results.png` 재사용. `case-common-tester.html`과 공개 GitHub 연결. |

기간, 팀 규모와 개인별 세부 역할은 확인된 값만 추가한다. Common Tester는 현재 상세에서 개인 기여와 전체 도구 동작의 구분을 보강할 필요가 있다. 이미지 시안에서는 프로젝트 전체 흐름을 보여주며, 검증되지 않은 개인 전담 역할을 붙이지 않는다.

기존 기록에 근거가 없는 성능 개선율, 사용 조직 수와 절감 시간은 만들지 않는다. Common Tester의 6개 테스트 통과 기록은 정책 판정 미확인 6개와 구분하여 상세 페이지에 유지한다. 전체 검증이 완료되었다는 문구로 축약하지 않는다.

상세 페이지는 기존 페이지를 활용하고, ‘문제 → 내 역할 → 적용한 방법 → 확인한 결과’의 읽는 순서를 맞춘다. 공개 데모가 확인되지 않으면 데모 버튼을 추가하지 않는다.

## 6. 화면과 동작 기준

- 색상은 기존 잉크색 `#102849`, 푸른색 `#387ed4`, 옅은 배경 `#edf5ff`를 중심으로 사용한다.
- 콘텐츠 폭은 기존 최대 1180px을 유지한다. 본문 글자는 16px 안팎으로 두고 보조 정보의 대비를 확보한다.
- 데스크톱의 기술 분류는 왼쪽 제목과 오른쪽 기술 목록, 프로젝트는 왼쪽 미리보기와 오른쪽 설명으로 정렬한다.
- 700px 이하에서는 한 열로 전환하고 기술 칩은 줄바꿈한다. 메뉴와 긴 기술명이 가로 스크롤을 만들지 않게 한다.
- 프로젝트 미리보기와 상세 이동 링크를 분명하게 구분한다. 링크 안에 또 다른 버튼이나 링크를 넣지 않는다.
- 호버 없이도 모든 역할, 기술과 링크가 보이게 한다. 키보드 포커스와 움직임 줄이기 설정을 지원한다.
- 스크롤 등장 효과는 보조로만 사용한다. 초기 로딩 상태에서 콘텐츠를 숨기거나 탐색을 막지 않는다.

검증은 실제 화면 크기, 긴 문구 줄바꿈, 이미지 대체 텍스트, 포커스 표시와 내부 및 외부 링크를 중심으로 한다. 콘텐츠와 스타일 변경을 위해 별도 테스트 프레임워크를 추가하지 않는다.

## 8. 이미지 시안의 해석

이미지는 image_gen 내장 도구로 만든 구성 제안이다. 실제 구현 화면이나 프로젝트 원본 캡처가 아니다. 최종 시안은 기존 첫 화면과 소개의 구성 유지, 프로젝트와 기술 및 자격증 보강을 나눠 보여준다. 첫 화면 시안은 실제 `assets/profile-photo.jpg`를 사진 참조로 사용한다. 이미지에 나타난 프로젝트 미리보기는 설명용 구성 예시이며, 구현에서는 위에 명시한 실제 캡처 또는 표시된 재구성 화면을 사용한다.

최종 생성 프롬프트는 같은 폴더의 `2026-11-16-legacy-portfolio-image-prompts-v2.md`에 기록했다. 초기 프롬프트 파일은 미채택 기록이다.

최종 시안:

- `portfolio-v2/01-existing-design-preserved.png`: 기존 사진, 중앙 첫 화면과 대화형 소개 유지.
- `portfolio-v2/02-projects-skills-certifications.png`: 프로젝트, 기술, 자격증 보강. ADsP 2026.11 포함.
