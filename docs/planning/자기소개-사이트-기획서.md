# 권현성 자기소개 사이트 기획서

작성일 2026년 10월 24일

## 1 기획 방향

- 목적: 짧은 경력 요약에서 상세 구현 기록으로 연결
- 대상: 프론트엔드 채용 담당자와 실무 개발자
- 지원 방향: B2C 선호
- 전달할 강점: 개발에 대한 관심, 직접 구현하고 기록하는 습관, 세부 동작을 챙기는 태도
- 참고: [김리안 사이트](https://www.liankim.kr/resume)의 경력 서술과 상세 글 연결 방식
- 형식: 한국어, 텍스트 중심, 프로필 사진 없음
- 구현: 기존 HTML과 CSS 활용
- 조사 근거: [사전 조사와 코드 근거](./사전조사-및-코드근거.md)

- 제목: 개발이 재미있어서, 직접 만들고 기록합니다.
- 설명: Vue와 React로 화면을 만들고, 반복되는 UI와 데이터 흐름을 정리해 왔습니다.
- 보조 설명: 실무에서 생긴 궁금증은 개인 프로젝트로 구현하며 확인합니다.

### 대표 카드

| 제목 초안 | 구현 내용 | 기술 |
| --- | --- | --- |
| 여러 화면에서 같은 테이블과 버튼을 쓰도록 | 공통 UI TF에서 구현과 개선에 참여 | Vue 3, TypeScript, Ant Design Vue |

- 배포 주소는 현재 동작 확인 후 연결

## 4 경력 페이지

### 공통 형식

- 회사 / 재직 기간 / 직무
- 제품과 사용자 설명 한 문장
- 기여별 배경 / 구현 / 결과 또는 제공 동작 / 기술
- 관련 상세 기록 링크

### 오케스트로

- 기간: 2023.09부터 현재
- 제품: 여러 클라우드와 인프라 자원을 관리하는 CMP
- 담당: 모니터링, 장비 관리, 서비스 신청 화면
- 공동 기여: 모노레포 설정, 공통 UI TF, 다국어
- 조직 규모: 사용자 답변 기준 개발본부 약 60명, 5팀
- 표기 기준: 개발본부 인원을 프론트엔드 인원이나 컴포넌트 이용자 수로 쓰지 않음

| 기여 | 요약 내용 | 상세 연결 |
| --- | --- | --- |
| 모노레포와 공통 UI | pnpm, Nx, 공통 테이블과 버튼, Storybook, 여러 팀 재사용 | shared-ui.html |
| 로그와 알람 | 검색 조건, API와 Query 키, 추가 조회, 통계, 정책 입력 | log-explorer.html |
| 인프라 장비 | 유형별 입력, 등록과 수정, 검증, 목록 갱신 | equipment-forms.html |
| 서비스 카탈로그 | 일반 신청과 프로비저닝 조건, 동적 입력, 첨부와 제출 | 경력 본문 |
| 한영 문구 | vue-i18n, 도메인별 메시지, 모니터링과 거버넌스 적용 | localization.html |

### 경력 문구 초안

- pnpm과 Nx 기반 모노레포에서 공통 테이블과 버튼 개발 및 개선에 참여했습니다.
- 팀마다 달랐던 UI 표현과 동작을 공통 컴포넌트로 맞추고 Storybook 가이드를 제공했습니다.
- Vue 3, Pinia, TanStack Vue Query로 검색 조건과 정렬을 연결한 로그 조회 화면을 구현했습니다.
- VeeValidate와 Yup으로 장비 유형별 등록과 수정 폼의 입력 검증을 구성했습니다.
- 서비스 카탈로그의 신청 유형과 사용자 포털 조건에 맞춰 입력과 제출 흐름을 구현했습니다.
- vue-i18n으로 모니터링과 거버넌스의 문구를 한국어와 영어 리소스에 연결했습니다.

## 5 상세 기록

### 공통 순서

1. 작업 배경과 담당 범위
2. 처리해야 했던 조건
3. 입력부터 상태, 조회, 렌더링까지의 흐름
4. 세부 구현과 자체 도식
5. 확인 가능한 선택 이유와 대안
6. 제공 동작과 확인된 결과
7. 한계와 검증 범위
8. 관련 기록

- 첫 화면: 제목 / 회사 / 역할 / 기술 / 한 문장 결과
- 본문 앞: 목차
- 글 끝: 경력과 기록 목록 링크
- 회사 코드: 공개 가능한 자체 도식과 독립 예시로 설명
- 구분: 구현 조건과 실제 장애 이력, 재현 결과와 운영 결과

### 공통 테이블과 버튼

- 제목: 여러 팀이 쓰는 테이블과 버튼의 동작을 맞추기
- 배경: 개발자마다 UI 형태와 동작이 달랐다는 사용자 설명
- 구현:
  - Ant Design Vue 기반 공통 컴포넌트
  - TypeScript 속성, 컬럼 타입, 슬롯으로 화면별 차이 수용
  - 헤더 실측 폭을 컬럼 상태와 colgroup에 반영
  - 버튼 로딩 표시 지연과 타이머 정리
  - Storybook 사용 예와 속성 가이드
- 도식: 공통 UI와 업무 화면의 관계 / 테이블 너비 동기화
- 결과: 여러 도메인에서 같은 인터페이스와 동작 재사용
- 표기: TF 기여, 전체 제작과 생산성 개선율은 근거 확보 전 보류

### 로그 조회와 렌더링

- 제목: 로그의 추가 조회와 화면에 그리는 범위를 나누기
- 구현:
  - 기간, 필터, 정렬을 Query 키와 요청 조건에 연결
  - 50개 단위 조회, 마지막 ID와 타임스탬프를 다음 커서로 사용
  - 스크롤 근처 행과 위아래 spacer로 화면 구성
  - 조건 변경 시 스크롤과 렌더링 범위 초기화
  - 같은 필터 값으로 불필요하게 상태를 갱신하지 않는 처리
- 도식: 필터 → 조회 → 결과 합치기 → 렌더링 범위 갱신
- 한계: 고정 행 높이 전제, 조회 데이터는 메모리에 유지
- 수정: 첨부 코드에서 확인되지 않은 isLogPageActive 사례 교체
- 성과: FPS, 응답 시간, 요청 감소율은 측정 근거가 있을 때 추가

### 장비 유형별 입력 폼

- 제목: 장비 유형에 따라 달라지는 등록과 수정 폼 구성하기
- 대상: HOST / SWITCH / STORAGE / RACK
- 구현:
  - 공통 입력과 하위 유형별 폼
  - VeeValidate와 Yup 검증
  - 수정 데이터 초기 반영
  - 날짜와 관리자 데이터 변환
  - 유형별 payload와 생성 또는 수정 API
  - 성공 후 draft 정리, 목록 쿼리 갱신, 목록 이동
- 도식: 공통 폼 → 유형별 입력 → 검증 → 전송
- 결과: 유형과 작업 모드에 맞는 입력을 같은 등록 흐름에서 처리
- 관련 기능: 서비스 카탈로그의 조건부 폼은 경력에 별도 표시

### 한영 문구 관리

- 제목: 여러 패키지의 화면 문구를 한영 리소스로 관리하기
- 개인 기여: 사용자 답변 기준 모니터링과 거버넌스
- 구현:
  - vue-i18n 공통 인스턴스
  - 한국어 기본값과 fallback
  - 도메인별 한국어와 영어 메시지 병합
  - 공통 useI18n 훅
  - 화면 문구와 검증 메시지 적용
- 도식: 공통 메시지와 도메인 메시지 → i18n → 화면
- 한계: 일부 한국어 하드코딩과 영문 파일 내 한국어 문자열 잔존
- 확인 범위: 리소스 구조와 적용 사실, 전체 번역과 실시간 전환 완료는 미확인

- 후속 후보: Electron 프리뷰, 카탈로그 상세 글, 개인 프로젝트 심화 기록
- 추가 요구 시: PDF 이력서, 영문, 별도 블로그 시스템

## 9 검토 기준

- 주요 주장에 코드 또는 사용자 답변 근거 연결
- 개인 기여와 프로젝트 전체 구현 구분
- 기술을 실제 기능과 함께 설명
- 미측정 성능 수치와 개선율 추가 금지
- 회사 코드, 데이터, 내부 주소를 배포 폴더에 포함하지 않음
- 소개 → 경력 → 상세 기록 이동 확인
- 직접 접속, 목차, 목록 복귀 확인
- 360px 모바일과 데스크톱의 표, 도식, 본문 확인
- 키보드 초점, 링크 이름, 페이지별 제목과 설명 확인
- 원본 프로젝트 실행과 성능 측정은 이번 조사 범위에 포함하지 않음
