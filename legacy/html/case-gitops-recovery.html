BEYOND FE / 현장 장애 조치

GitOps 배포 복구

기존 Argo CD 저장소 연결에 변경된 GitLab 비밀번호가 반영되지 않아 배포가 멈췄습니다. 연결을 복구한 뒤 새 Pod에서 발생한 Harbor Pull 401까지 추적해 배포를 정상화했습니다.

GitLab 연결 복구Harbor Pull 401해결 결과

01 / ARGO CD / GITLAB

기존 저장소 연결에 새 비밀번호가 반영되지 않았습니다

제가 Settings > Repositories에서 대상 GitLab 연결의 Failed 상태를 확인했습니다. GitLab 비밀번호는 변경됐지만 Argo CD에 등록된 기존 경로에는 이전 인증 정보가 남아 있었습니다.

제가 한 조치

기존 저장소 연결의 인증 정보를 갱신하고 Connection Successful을 확인했습니다. 중단된 Application 동기화도 다시 진행됐습니다.

02 / HARBOR / CONTAINERD

동기화 다음 단계에서 이미지 Pull만 401이 났습니다

dev의 ccms-dev-user 신규 Pod가 ImagePullBackOff로 멈췄습니다. 빌드와 Harbor Push, Argo CD 반영은 성공했습니다. 저는 새 Pod의 이벤트를 보고 실패 범위를 워커 노드의 이미지 Pull 단계로 좁혔습니다.

인증 경로 확인

imagePullSecret.create: false

클러스터에 해당 Secret 없음

실제 Pull 경로: 워커 노드 containerd

원인Harbor 비밀번호 변경이 워커 노드 containerd 인증 설정에 반영되지 않았습니다.

조치제가 /etc/containerd/config.toml의 Harbor 인증 정보를 갱신하고 containerd를 재시작했습니다.

03 / RESULT

Git 동기화와 이미지 Pull을 모두 복구했습니다

기존 저장소 연결의 인증 정보를 갱신해 Argo CD 동기화를 재개했습니다. 이후 워커 노드의 Harbor 인증을 갱신했고, dev와 stg에서 신규 Pod의 이미지 Pull과 배포가 정상으로 돌아왔습니다.
