KUBERNETES OPERATIONS

폐쇄망 Kubernetes
이미지 패치

폐쇄망에 반입한 두 이미지를 Nexus에 등록하고, Push 주소와 Pod의 Pull 주소가 다른 환경에서 두 Deployment를 새 이미지로 교체했습니다.

제가 한 일
이미지 반입, Nexus 등록, Deployment 교체
대상
trb-app의 pipeline-api, react-app
기술
SFTP, nerdctl, kubectl, Nexus
이미지 반입Nexus 등록이미지 교체배포 결과

01 / IMAGE TRANSFER

이미지 tar를 반입하고
기존 Deployment를 확인했습니다

pipeline-api.tar와 react-app.tar를 SFTP로 반입했습니다. 작업 대상 클러스터를 확인한 뒤 두 Deployment의 YAML을 저장해 기존 이미지 주소도 함께 남겼습니다.

02 / IMAGE REGISTRY

tar 안의 실제 이미지 이름을 확인하고
Nexus 주소로 재태깅했습니다

nerdctl load 뒤 nerdctl images로 tar 안에 저장된 원본 이미지 이름을 확인했습니다. tar 파일명은 이미지 이름과 같지 않을 수 있어, 출력된 Harbor 주소를 원본으로 삼아 Nexus Push 주소로 재태깅했습니다.

03 / DEPLOYMENT UPDATE

Push 포트가 아닌 Pull 포트를
Deployment에 지정했습니다

Nexus 업로드에는 :50000, Kubernetes Deployment에는 Pull 주소인 :55000을 사용했습니다. 업로드 성공과 Pod의 이미지 수신은 다른 경로이므로, kubectl set image에서 두 Deployment의 Pull 주소를 각각 지정했습니다.

kubectl set image가 Rolling Update를 시작하므로, 두 컨테이너에 지정한 Pull 주소와 태그가 변경의 핵심입니다.

04 / DEPLOYMENT RESULT

두 서비스가 새 이미지를
사용하는지 확인했습니다

두 Deployment의 롤아웃 상태를 확인하고 실제 IMAGE 필드가 :55000 주소와 새 태그를 가리키는지 대조했습니다. 이어 새 Pod의 상태와 애플리케이션 로그까지 확인해 이미지 교체가 배포로 이어졌는지 봤습니다.
